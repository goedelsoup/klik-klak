**This is the testimony row the catalog was missing for AGS.** The three AGS entries
([ags-manual](ags-manual.md), [ags-272-manual](ags-272-manual.md), [ags-source](ags-source.md))
are artifacts. They record what was built. This entry records what the maker and the authors said
about it. `.yidam/decisions/testimony.yml` named that gap as the reason three questions stayed
open, and `.yidam/decisions/ags-testimony.yml` is the record of reading this entry against them.

It is a **forum**, and two kinds of standing need keeping apart:

- **Chris Jones's own posts** are a maker's testimony, the same kind of source as
  [twp-dev-diary](twp-dev-diary.md) is for the other house. He posts as *Pumaman*, marked
  "Creator of AGS" and "Administrator".
- **Everyone else's posts** are other authors' testimony. They say what using AGS was like for
  them and what the community taught. One beginner thread is not a base rate.

**A name to keep straight.** The moderator of the Advanced Technical and Beginners' Technical boards
posts as *Gilbert*, marked "Local Moderator". That is not Ron Gilbert. Everywhere else in this
corpus "Gilbert" means Ron Gilbert and Terrible Toybox, so this entry and every node citing it says
"the forum moderator Gilbert" whenever it means him.

## What was read

Read 2026-11-26, three pages: reply #189 in the beta thread, "Suggestion for a more User-Friendly
Adventure Game Studio" page 2, and "OBject appearing after dialog has ended" page 1.

Each page was read whole in a browser. The quotations are copied from the page as rendered.

**Chris Jones, 15 August 2007, reply #189.** He was answering a user who could not find the
Interaction Editor in the 2.8 beta, the beta that became 3.0:

> Yes, the inteaction editor has been scrapped. I had a long, hard think about this but basically I
> felt that the Interaction Editor in 2.72 was too simple to really be able to make a game with, and
> that it gave a false sense of "easiness" of game creation to people who would very quickly come
> across something that it didn't support, and get frustrated with it.
>
> I think the way forward is to have some sort of auto script-generating tool (maybe as a plugin)
> that works in a similar way to the interaction editor but it basically creates the script code
> for you.

The spelling "inteaction" is his.

**"Suggestion for a more User-Friendly Adventure Game Studio", page 2.**

- The forum moderator Gilbert, reply #29, Tue 02/10/2007 03:18:57, gives the same reason
  secondhand. The editor is "never complete to a point that it's really useful (you can't even make
  a simple game without any scripting)", and it "requires a lot of work to maintain and update". He
  then links to Jones's post above ("some comments on it by CJ here").
- RickJ, reply #30, quotes Jones's second paragraph.
- On the users' side: bolfar (#24) says the editor "got me started with AGS", and that "any new user
  with no scripting experience would" miss it. subspark (#25) and Sylvr (#27) say it helped them
  learn. Khris (#21) says "there's no need for the IE at all".
- SupSuper (#37) describes what 3.0 kept: "Think of it as an I.E. with only a Run Script option."
- Jones's own reply on this page (#23) is advice on learning to script. It says nothing about the
  removal.

**"OBject appearing after dialog has ended [SOLVED]", page 1 (2013).** A beginner asks how to make an
object appear after a conversation and then be picked up. Slasher (#2) answers with a recipe that
writes both halves by hand: make the object visible, walk to it, "make object visible = false and
then add inventory object to player". Slasher's second example (#10) does the same thing:
`object[7].Visible=false;` and then `cEgo.AddInventory(isatellite);`. The rest of the thread is
about an object index error, which is unrelated.

## Second reading, for the three open questions

Read 2026-11-26, one page at a time in a browser, against the three questions
`.yidam/decisions/ags-testimony.yml` left open. `.yidam/decisions/forum-witnesses.yml` is the record
of it. Quotations are copied as rendered, misspellings included.

### Whether anything shipped as Jones's "auto script-generating tool"

**"Editor plugin: Simple Scripter 0.01 for AGS 3.0" (February 2008).** SupSuper opens it "Ever since
it was announced that AGS 3.0 wouldn't have an interaction editor". The plugin lets an author add
functions and properties while "Simple Scripter writes the code for you", and it reads script back
into that form as well as writing it. Version 0.01, dated 1 February 2008. By SupSuper's own account
it "works with a rather strict coding style (only one expression per line)" and is "far from
complete"; conditionals are unsupported (#7).

- monkey0506 (#2): `if` and `while` give "Unrecognized expression".
- RickJ (#3) suspects the maintenance cost "is pretty much why the Interaction Editor and it's
  predecessor, Graphical Scripts, have went by the wayside", and suggests dropping the parsing of
  existing code.
- Groogokk (#4): "Without an IE, I'll very probably stick to 2.72."
- Pumaman (#5, Sun 03/02/2008): "the most important point at which people need scripting help is
  when creating their first event handlers". His later replies (#9, #12) are API pointers.
- The thread ends on 19 February 2008 with no further release in it.

**"Improving the AGS scripting language", page 2.** monkey0506, reply #24, 17 June 2012, would
"advocate doing something like what SupSuper began, but unfortunately never completed".

### Whether authors pay for the missing pickup bundle

- **"AGS saying term is wrong?" (2010).** A beginner's `oObject0_Interact` adds the cup to the
  inventory and then writes `icup.Visible = true;`, and never hides the room object. The compiler
  stops it only because inventory items have no `Visible`. Matti (#1): "you must have an object
  representing the cup and make that one disappear". Khris (#2, 20/04/2010 22:44:49): "room objects
  and inventory items are two completely seperate things as far as the engine is concerned; the idea
  that both represent the same object in the game world is in the designer's mind only."
- **"object move" (2012).** A beginner's `oCoins_Interact` moves the object and adds the item, with
  no hide. Crimson Wizard (#1, 25/09/2012 23:39:09): "you do not hide object after inventory item was
  given to player", because "the fact that item is given to player does not mean object will
  dissapear on its own". His #6 states the pair as what "people usually do": hide the object, add
  the item.
- **"How to remove an item from the inventory when used?" (2020), two pages.** The pickup and its
  undo are each written as two halves by hand, `oPillow.Visible = false;` with `AddInventory`, and
  `oPillow.Visible=true;` with `LoseInventory`. The pillow stays in the inventory after it is put
  back. Crimson Wizard (#20, 06/09/2020 18:04:34) finds an `iPillow_Interact` in the global script
  that adds the item again whenever it is clicked in the inventory, so the item is held twice and
  one `LoseInventory` leaves one behind. The room object and the held item disagree.

### Whether anyone notices an orphaned dialogue option

- **"Dialog puzzle" (2004).** Ishmael (#3) answers a beginner with a fifteen-option worked example.
  In its option 10, `option-off-forever 14` is immediately followed by `option-on 14`, and the
  manual says a permanent off cannot be undone. Option 15, *"The man looks like he doesn't want to
  talk with you right now."*, is enabled only from the `dialog_request` that option 14 runs, so after
  option 10 nothing can reach it. [inference] — read from the posted script against the manual's
  semantics; the script was not run. `option-on 15` looks like what was meant. The same option has a
  second slip, `option-off forever 12`. The beginner's last post is before the example; nobody in the
  thread mentions either.
- **"(Solved) Turning Dialog options on and off" (2015).** Dannymac247's `@S` has no `return`, so the
  dialog falls through into option 1 and switches options 2-5 back on: the player sees more than was
  meant. Khris (#2) fixed it and is "not really sure why things get screwed up like that"; Snarky
  (#3) names it "fall-through". Dannymac247 says an earlier thread had the same problem and never
  said what was wrong.
- **"DoDialog options turned off error..." (2011).** The one reachability condition AGS checks
  itself: starting a dialog whose options are all off stops the game with "DoDialog: all options have
  been turned off" (Khris, #3). Ryan Timothy B (#4) thinks this "should be looked as a glitch", and
  the thread spends its length on ways to close a dialog when the last option is spent.
- **"Marking dialog options as read/ unread." (2009).** thezombiecow wants to mark an option unread
  again "so the player knows there's potentially new stuff by clicking it". An author caring that
  players miss content behind an option already taken; no option is unreachable in it.
- **"Dialog options problem" (2019) and "More complicated dialog? help!" (2005)** are the leads
  named as topic 56985 and topic 24248. The first is about option text being spoken and the second a
  request answered with the manual's command list. Neither bears on the question.

## What was looked for and not found — read this before citing

**Whether AGS authors left a room object on screen after `AddInventory`, and shipped it, is not
shown.** The second reading above found authors leaving it out (2010, 2012) and the two halves
coming apart (2020), every time in a game still being written and every time caught by a person on
this board. Nobody here found a released game carrying the window. That is the half of the question
a forum is the wrong place to answer: a shipped bug is reported to the game's author, not in
Beginners' Technical Questions. [inference]

**Whether AGS authors experienced an orphaned dialogue option as a loss is still not shown.** Four
dialog threads were first read by a fetching agent: guga2112 (2020), TheRoger (2011), Dannymac247
(2015) and Fluxpuppy (2014). The Dannymac247 thread has now been read here and matches the agent's
report; the other three were not found again and still carry no tag weight. Every dialog thread read
here is a how-to question or a visible malfunction. None is an author noticing that content they
wrote was never shown, and the one orphan found was in a helper's example, unnoticed by anyone in
the thread.

**The forum rate-limits.** A burst of automated reads earlier in this retrieval returned
`503 Service Unavailable` with `Retry-After: 3600`. The pages above were read one at a time after
that hour had passed.

## What the forums hold that nobody here has looked at

Nearly all of it. The beta thread cited above runs to more pages than the one page opened here, and
Jones answered questions about 3.0 across it. The other 2007-2008 beta threads are unopened. So is
everything Jones wrote after that, and so is most of the Beginners' Technical Questions archive.
The forum's own search was not used, because the rate limit made automated reads the wrong tool for
it.

or the other, but not both at the same time", "Pick up and Object", "Walking to object before picking
it up?", "Exit a dialog when all options are gone", and topics 28675, 19602 and 28130. The guga2112,
TheRoger and Fluxpuppy dialog threads were not found again. Whatever became of Simple Scripter after
February 2008 outside that thread was not looked for.
