# crates

Rust crates implementing the domain computer — the retrieval, calculation, and feature
engineering capabilities that agents use to work with the corpus without loading it
wholesale into context.

See [crates conventions](../.yidam/.vendor/prelude/guidelines/directories.md#crates) for the three
capability types (connectors, calculators, feature engineering) and the index layer.

This directory is empty at genesis and that is the honest state. The domain computer here
would be unusual: the corpus's subject *is* a Rust engine, so `crates/` risks being read as
the engine itself. It is not. The engine, when it exists, is what the corpus describes;
`crates/` is the instrument that makes the corpus queryable, and the two must not be
conflated — a calculator that computes vocabulary coverage is a research tool, while a
renderer is the object under study.

The first crate expected here is a **vocabulary-coverage calculator**: given the seeded
`interaction` nodes and the `verb` vocabulary they draw on, report which verbs no
interaction exercises and which interactions need a verb the vocabulary does not declare.
That is the arithmetic behind the central question, and it is the only computation this
corpus currently needs that a person cannot do by reading. It is not written yet — the
corpus must first hold enough interactions for the answer to mean anything.

No connectors are planned. The sources this domain draws on are engine documentation and
source releases, which are read once and cited, not polled — a connector against a manual
that has not changed since 1997 would be a refresh loop over a fixed file.
